# 成员清退可靠性修复验收

## 业务边界

- 自动清退由 `MEMBER_AUTO_CLEARED` 审计定义，进入自动清退、冷却和重新加入生命周期。
- 主动退团由 `MEMBER_VOLUNTARILY_LEFT` 审计定义，进入 `EXEMPT`，不得新写 `clearedAt`，也不得计入自动清退累计人数。
- 主动退团记录在“用户与公会”独立展示；系统设置只展示自动清退记录。

## 任务可靠性

- 维护任务使用稳定 ID 游标分页，不受 500 人上限影响。
- 单成员执行失败写入匿名资格 ID 和错误摘要，后续成员继续处理。
- Worker 仅在初始化、预警、清退或失败发生时写聚合日志；单条失败和清退后不变量异常发送告警。
- 每日巡检记录未来 24 小时/7 天到期人数、涉及积分和订单，并检查到期未清退、漏发预警、余额、Session、订单、视频和审计一致性。
- 已被后续健康周期恢复的历史周挑战失败保留在报告中，但不再让每日巡检失败。

## 验收步骤

1. 构造主动退团记录，确认自动清退累计人数和名单不变，主动退团页显示原因、时间、积分和订单数。
2. 构造自动清退记录，确认仍显示在自动清退与冷却名单，并可进入重新加入流程。
3. 用 501 条模拟资格记录验证游标分页；第 250 条抛错后其余 500 条仍完成。
4. 构造到期未清退、漏发预警、非零余额和残留 Session，确认巡检逐项报告。
5. 在 `390×844` 与 `1440×900` 验证两个名单、空状态、加载、搜索和无页面级横向溢出。

## 发布观察

发布后核对 migration 影响行数与当前主动退团审计数量；观察 Worker 清退聚合日志、每日巡检和告警通道。首次批量自动清退后运行数据对账，并保留发布前备份和回滚点。
