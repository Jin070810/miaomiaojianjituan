# v1.6 商城分类与会员权益验收

## 范围

- 商城分类改为真实筛选，分类由商品 `category` 字段驱动，不再使用固定装饰标签页。
- 当前商品在 migration 中按名称自动分类并生成基础标签；“妙妙一日女友体验权”等普通体验商品保持实物类型。
- 新增 `MEMBERSHIP` 兑换类型，仅用于视频平台、剪辑软件、办公与创作软件会员。
- 管理员可编辑分类、最多 6 个标签，并可按商品名重新自动分类。
- 会员权益商品可配置最多 8 个成员填写字段，支持单行文本、手机号、邮箱、数字、多行备注和下拉选择。
- 会员兑换资料按订单快照加密保存；管理订单时按 RBAC 解密查看并执行“开通”。

## 数据与安全不变量

- migration 只新增枚举值、字段和索引，不删除或重写历史订单字段。
- 已有兑换或榜单奖励引用的商品不会由 migration 自动改成会员权益类型。
- 自定义字段定义保存在商品上；提交时把字段标签、类型和值形成订单快照，后续修改商品不影响历史订单解释。
- 账号、手机号和邮箱等兑换值写入 `fulfillmentDataEnc`，接口列表只返回是否有资料，审计日志只记录字段数量。
- 兑换的库存预占、积分扣除、订单创建、审计日志和通知仍在同一事务中完成；字段校验失败不扣库存和积分。

## 自动化验收

- `tests/gifts.test.ts`：商品名分类、普通体验商品不误判、标签规范化、自定义字段和答案校验。
- `tests/points.integration.test.ts`：会员资料缺失时事务回滚、资料加密、审计脱敏、后台开通。
- TypeScript、普通测试、数据库测试、生产构建、依赖审计和 Docker 构建按仓库门禁执行。

## UI 验收

成员端 `390×844`：

- 分类标签可以横向滚动，点击后只显示对应分类商品。
- 商品卡显示分类/标签，长商品名、长标签和大积分值不溢出。
- 会员权益兑换表单按后台配置渲染；必填字段缺失时不能提交。
- 加载、空分类、售罄、余额不足、校验失败和兑换成功状态清晰。

管理端 `1440×900`：

- 可选择会员权益类型、编辑分类与标签、自动分类。
- 可添加、删除并配置最多 8 个兑换字段。
- 会员订单只在点击“查看资料”后加载敏感值，可执行“开通”、驳回和退款。

## 发布与回滚

- migrations：`20260728150000_gift_categories_membership` 先提交枚举值，`20260728150100_gift_catalog_classification` 再新增字段并回填，`20260728150200_gift_descriptive_tags` 补充名称特征标签，`20260728150300_refine_existing_gift_classification` 按完整现有目录复核结果修正宽泛关键词误分；拆分可避免 PostgreSQL 在同一事务中引用新枚举值。
- 发布前在生产副本核对自动分类结果，重点检查包含“会员”“月卡”“订阅”等词的存量商品。
- 应用版本可回滚；由于 PostgreSQL 枚举值和新增列保留，数据库不做向后删除。旧版本会忽略新增列。
- 发布后至少观察 30 分钟，检查兑换接口错误率、会员资料解密失败、订单履约状态和响应时间。
- 当前状态：`Ready for review`；staging、正式发布和发布后观察尚未执行。
