# 成长档案后台更新与只读查询

成长与成就原先在每次 GET 中扫描全部通过视频、更新档案/目标/勋章并创建通知；同一重算还位于视频通过、申诉通过和撤销的积分事务中。合成成员首次 GET 复现了 6 条 INSERT/UPDATE。

现在展示采用可重建的读取数据。账户、积分流水、视频状态、审计仍在原事务提交；成长展示允许短暂延迟，页面不得把首次尚未计算的数据显示为零。

## 数据链路

1. 新成员、有效视频数量/指标变化、周挑战已完成数量变化，由 PostgreSQL 触发器在源事务内更新该成员的 `MemberAchievementRefresh`。源事务回滚时，更新任务一起回滚。导入、维护和旧应用写入也会产生任务。
2. 同一成员的多次变更合并为递增 generation。待处理时间保留最早未解决请求，后续变更不能不断延后任务或掩盖积压。积分交易不再运行成长重算。
3. Worker 每 5 秒读取至多 20 项任务，每轮在任务之间检查 5 秒预算。领取使用短事务、`SKIP LOCKED` 和 60 秒租约，数据库时钟为准，避免不同进程时钟偏差。重算期间不持有任务行锁，不阻塞源事务提交更新意图。
4. 重算事务有 15 秒上限、10 秒 SQL 上限和 2 秒锁等待；同一成员用事务锁串行。最终提交必须仍持有有效租约，否则档案、勋章、目标及通知一并回滚。期间出现新 generation 时保持待处理，继续下一轮。
5. 失败保留上一版结果，按 5 秒起步指数退避，上限 15 分钟；退出后遗留租约可自然回收。通知使用原有固定去重键。Worker 退出等待当前投影任务结束后再关闭数据库。

源触发器只记录更新意图，不在 PostgreSQL 中计算成长、发送通知或写积分。直接修改视频 points 不改变经验公式，因此不单独触发重算。生日勋章继续由生日事务写入，不在普通创作勋章撤销集合内。

## 查询和计算边界

- 成就 GET 使用 PostgreSQL `READ ONLY`、`REPEATABLE READ` 事务，读取档案、当月目标、勋章、最多 3 条高光、最近 6 份复盘和任务状态。请求不创建档案、目标、任务或通知，也不搬运全部视频历史。
- 后台在数据库聚合总经验、指标、月份集合、8 周基线和当月进度。逐条取整后求和，保持原有公式；时间窗口显式按 UTC 存储与上海月份换算。新建月目标仍按原规则锁定，后续重算不重写目标基线。
- 响应保留原字段，增加可选 `projection` 状态。未初始化显示“成长档案更新中”；已有数据且待更新时保留上一版并说明延迟。积分以账户余额为准。
- 页面只在卡片/档案挂载且前台可见时，按 5、10、20 秒最多自动刷新三次；读取失败停止自动重试，保留手动刷新。Worker 停机不产生无限轮询。HTTP 保持 `private, no-store`。
- 每分钟有界检查缺失档案、月份切换及超过 24 小时的旧档案，重新排队；单次最多 100 名成员。已待处理的任务不重复排队、不覆盖退避和租约。已有月度复盘维持原先的历史快照规则。

## 核对、重建与监控

Worker 对重建失败告警；最早待处理任务超过 5 分钟时报告积压数和失败数，不把数据库连接细节发送到通知。重算的错误记录只保留通用错误码。

```bash
# 默认只读：任务积压概况
npm run growth:rebuild -- --status
# 显式只读：比较源数据与成长经验、等级、当月进度/完成状态、创作勋章
npm run growth:rebuild -- --check --all
npm run growth:rebuild -- --check --user-id MEMBER_ID
# 显式写任务：由 Worker 重建，不修改积分或历史目标
npm run growth:rebuild -- --enqueue --user-id MEMBER_ID
npm run growth:rebuild -- --enqueue --all
```

核对发现不一致时退出码为 1，同时说明是否已有待处理任务；排队与核对分开，不能在只读命令中偷偷修复。所有命令仅供有服务器权限的维护者使用，没有新增成员或管理员 HTTP 写入口。

## 迁移、验收与回滚

新增两项 migration：`20261003173000_achievement_projection_outbox`、`20261003174500_achievement_queue_wait_age`。增加任务表/源触发器、当月进度列和高光索引，保留原档案、勋章、目标与复盘；已有成员先排队，由新版 Worker 重建。这两项已在本地执行，不得再编辑。

发布前应在脱敏生产副本演练 migration、重建耗时与积压告警，比较核对报告，并确认首次补齐可能产生的达标勋章通知数量。数据库大表上的新增索引会占用资源，应纳入发布窗口评估。空库 CI 不能替代该演练。

集成测试覆盖只读 GET、源事务回滚、领取竞争、重建期间源提交、租约丢失后的最终提交回滚、崩溃租约回收、失败退避、撤销补偿、月切换、挑战完成计数及上海边界/逐条取整。另有 Worker 不重入/退出排空/失败恢复测试，以及 390×844、1440×900 的初始、延迟、加载、503 重试、空数据和有限自动刷新测试。CI staging 用真实 Worker 验证视频变更到档案生效、10 个并发 GET 不改写档案以及撤销后的更新。

应用回滚保留新增表、列和触发器。旧应用仍会同步重算，可能重新引入查询和积分事务的性能问题；旧 Worker 不消费新增任务，回滚期间积压可以保留并在前向恢复后重建。正式回滚应让 Web/Worker 使用同一旧版本，不能声称性能问题仍被解决。不得删除源视频、账本或审计来清理任务。
