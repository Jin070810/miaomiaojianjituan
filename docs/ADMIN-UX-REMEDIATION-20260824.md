# 管理后台体验修复验收单（2026-08-24）

## 背景与目标

线上巡检发现管理后台的主要操作按钮在部分页面呈现为“白字白底”，成员邀请入口没有实际行为，积分与生日运营页过长，高风险操作缺少一致的影响预览，部分内部状态码和技术错误直接暴露给运营人员。

本次修复目标是恢复核心任务的可见性和可操作性，并建立一套可复用的管理操作确认模式。范围仅包含前端交互、信息架构和文案，不修改数据库、接口权限、积分事务或业务状态机。

## 本次范围

- 修复后台按钮样式被成员端全局样式覆盖的问题，并补齐键盘焦点、禁用和危险操作状态。
- “邀请成员”跳转到系统设置中的入团申请链接，并定位到对应模块。
- 为积分调整、视频撤销、订单处理、账号状态、角色变更、榜单结算、公告发布/撤回、运营开关、生日库存和领奖撤回提供操作影响预览。
- 积分管理拆分为“人工调整 / 积分规则 / 积分流水”，预览明确展示选中成员的变动前后余额。
- 生日运营拆分为“运营概览 / 奖池库存 / 生日纠错 / 待处理窗口”。
- 积分流水类型和生日抽奖状态改为中文业务文案；周挑战生成错误默认收起到“技术错误”详情。
- 修复密码协助中心桌面端标题区域被压缩的问题。

## 验收条件

- 在 `1440×900` 和 `390×844` 下，管理后台页面无横向溢出或关键按钮遮挡。
- 用户与公会页的“邀请成员”按钮有清晰对比度，点击后可看到“入团申请链接”。
- 积分和生日页面一次只展示一个任务上下文，切换任务不丢失已填写内容。
- 批量积分扣减预览展示变动后余额；余额不足时禁止确认。
- 危险操作明确展示对象、变更前后状态和不可逆影响；关键撤回操作要求输入确认口令。
- 运营主界面不直接展示英文积分类型、生日奖品状态或模型原始错误。
- 后台样式修复不改变成员端按钮视觉。

## 风险与回滚

- 无数据库 migration、无新增依赖、无 API 响应变更。
- 风险集中在 CSS 层叠顺序、任务页条件渲染和确认弹窗拦截。
- 若 staging 发现阻断，可直接回滚本分支对应应用 commit；无需回滚数据库或 Worker。
