# 生日星愿运行手册

## 功能边界

- 首页和个人中心仅展示固定入口及当前成员自己的权益状态，不返回其他成员的生日信息。
- 今日寿星和未来 30 天生日只在成员主动打开生日墙后实时查询，不创建全员通知或通知红点。
- 生日墙默认不公开。关闭公开状态立即生效；完整生日只在本人资料接口中解密返回。
- 生日个人通知只用于抽奖开放、未抽奖提醒、首条祝福和商品领奖提醒。
- `BIRTHDAY_PROGRAM` 控制生日资料、生日墙、祝福、年度纪念和个人提醒；`BIRTHDAY_REWARDS` 单独控制抽奖和作品积分加成。两个开关默认关闭。

## 数据与事务

新增 migration：

1. `20260807090000_birthday_wishes`：生日资料、年度权益、祝福、奖池、奖品、生日订单关联和作品加成快照。
2. `20260807100000_birthday_effective_at`：记录当前生日的独立生效时刻，阻止生日发生在等待期内时补发权益。
3. `20260807110000_birthday_prize_revoke`：支持管理员撤回未领奖商品并在同一事务返还商城库存。
4. `20260807120000_birthday_onboarding`：记录成员首次查看生日权益说明的时间，避免跨设备重复展示。

完整生日使用现有敏感字段加密组件保存，普通墙接口只返回昵称、头像和月日。管理员纠错审计只记录月日、生效时间和原因，不记录完整生日。

抽奖、积分入账、商品预留、零积分订单、过期/撤回返库、作品加成和撤销均在数据库事务中执行。年度权益以 `(userId, benefitYear)` 唯一，抽奖结果和积分流水分别使用唯一幂等键。商品档按奖池剩余预留数量加权，竞争失败会重新选择库存或发放该档保底积分。

## Worker

Worker 的维护循环负责：

- 将等待满 7 天的生日资料切换为当前资料；
- 在生日当天生成年度纪念权益；
- 仅向寿星本人发送抽奖开放和未抽奖提醒；
- 在领奖第 7、23 天发送去重提醒；
- 将超过 30 天仍未领取的商品标记过期并返还商城库存。

2 月 29 日生日在非闰年于 2 月 28 日处理。所有边界使用 `Asia/Shanghai`，Web 与 Worker 必须部署同一 commit。

## 发布步骤

1. 保持两个生日开关关闭，备份数据库并记录校验值。
2. 在生产副本执行 `prisma migrate deploy`，核对三条新增 migration 和索引。
3. 部署同版本 Web 与 Worker，验证 `/api/health`、Redis 和 Worker 维护循环。
4. 在后台配置生日商品奖池，核对每个商品的商城库存扣减量和生日预留量。
5. 先开启 `BIRTHDAY_PROGRAM`，完成资料登记、隐藏、生日墙和祝福验收。
6. 核对预算和奖池后开启 `BIRTHDAY_REWARDS`，完成抽奖、积分、商品领奖和作品加成验收。

系统不回填生日数据，成员上线后自主登记。功能开启后 7 天内不会产生由新登记资料带来的生日权益。

## Staging 验收记录

发布单至少记录以下结果和截图：

- `390x844`、`1440x900` 的登记、待生效、隐藏、无寿星、今日寿星、抽奖、祝福、领奖、加载和错误状态；
- 首次进入展示生日权益说明，确认后同一账号再次进入不重复展示；成员端不展示抽奖概率或策略版本；
- 普通成员未打开生日墙时无法获得其他成员生日，且不会收到他人生日通知；
- 并发抽奖只有一个结果，单份商品不超卖，商品无库存时发放正确保底积分；
- 自动通过、申诉通过、撤销作品的生日加成和年度 500 分额度一致；
- 生日密文不出现在普通接口、应用日志和审计明文中，后台接口拒绝非管理员；
- 领奖过期和管理员撤回均准确返库，重复执行不重复返库。

## 回滚

异常时先关闭 `BIRTHDAY_REWARDS`，需要隔离整个模块时再关闭 `BIRTHDAY_PROGRAM`。关闭生日开关不得影响首页、投稿、积分、商城、排行榜或个人中心其他功能。

已经产生的积分、奖品、订单和审计记录保留，不删除 migration、不直接回退数据库。积分或库存错账通过新的审计补偿事务处理；应用版本回滚前确认旧版本能够忽略新增表、字段和枚举，否则使用前向修复。
