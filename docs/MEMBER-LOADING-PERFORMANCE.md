# 成员端首屏加载约定

## 原因与改动

此前根布局同时加载中文无衬线可变字体、三种字重的中文衬线字体和管理端主题。登录页冷缓存触发 19 个字体请求，成员首页还直接下载用于小卡片的 1,024,560 字节 PNG。生日、成就详情、三类记录组件也静态引入首页。

现在正文和标题使用设备自带的中文字体栈，不下载 Fontsource 字体包；管理端主题由 `/admin`、`/reviewer` 自身引入。共享样式仍保留在根布局，避免一次调整混入大规模 CSS 重排。不同操作系统的字形会略有差异，发布验收应检查 Windows、Android 和 iOS 的实际显示。

首页成长插画按 124px、详情插画按实际显示尺寸通过 Next Image 输出；生日入口插画也使用明确尺寸。生产镜像必须保证 `.next/cache` 对运行用户可写，以便复用图片转换结果。

生日、成就详情、积分记录、送积分记录和兑换记录使用 `next/dynamic`，进入相应页面才加载。首页的生日入口和成就摘要是独立的小组件。加载期间提供等待提示，组件加载失败可返回首页或重新加载；现有接口失败重试保留。参照 [Next.js 按需加载](https://nextjs.org/docs/app/guides/lazy-loading) 和 [Image 组件说明](https://nextjs.org/docs/app/api-reference/components/image)。

成就接口在摘要卡片进入视口附近（150px 提前量）或直接进入档案时请求。没有 IntersectionObserver 的浏览器退回正常加载。首页、成长、周任务仍并行请求：成长行动建议依赖周任务的可领奖状态，不能为了减少请求而延迟到用户滚动至周任务卡片后才读取。大型视口和当前 390px 页面中，成就卡片在提前量内，最终仍有 5 个首页相关 API 请求；本次不宣称减少所有会话的请求总量。

## 本地测量

2026-10-03，Windows Chromium，`next build` + `next start`，本地 PostgreSQL/Redis，`http://127.0.0.1:3213`。每个页面/视口取 3 个全新浏览器上下文，无浏览器缓存，等待首屏内容、字体和网络空闲后读取 Performance Resource Timing；测试成员无视频历史。前版是 #111 构建，其前端与 main 一致。单位为实际传输字节，包含浏览器计入的响应头开销。

| 页面/指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 登录 390×844，总传输量 | 1,312,148 B | 318,870 B |
| 登录，请求数 | 37 | 14 |
| 登录，字体请求/传输量 | 19 / 854,548 B | 0 / 0 B |
| 首页 390×844，总传输量 | 3,002,168 B | 343,537 B |
| 首页 390×844，请求数 | 60 | 25 |
| 首页 1440×900，总传输量 | 3,060,116 B | 343,537 B |
| 首页 JavaScript | 191,614 B | 183,319 B |
| 登录/首页 CSS | 167,613 B | 29,051 B |

登录传输量降低约 75.7%，移动首页降低约 88.6%。本地响应速度与生产地域、带宽、用户历史数据、服务器负载不同；这些比例是实验中的资源体积变化，不代表生产 LCP 或接口延迟同比例下降。上线后应单独比较冷缓存、弱网、图片缓存命中率和真实用户 LCP/INP/CLS 的分布。

## 验证和维护

`tests/e2e/member-loading.spec.ts` 在 390×844 和 1440×900 验证登录、首屏、未打开组件不下载、无网络字体、成就请求时机、真实组件下载等待、503 后重试、空数据、禁用操作，以及生日/成就/三类记录导航。故意中断生日组件下载后验证错误提示和返回首页，不把浏览器框架白屏当作可接受结果。测试账号独立创建和清理，不修改全局业务开关。

```powershell
$env:PLAYWRIGHT_PROD_SERVER="1"
# 先设置隔离数据库、Redis、测试会话密钥和 SESSION_COOKIE_SECURE=false。
npm run build
npx playwright test tests/e2e/member-loading.spec.ts --project=member-loading-mobile --project=member-loading-desktop
```

本地可将 `PLAYWRIGHT_EVIDENCE_DIR` 设置为仓库外目录保存截图。CI 将截图收集到已有的 Playwright artifact；全量 E2E 保留 320–430px、横屏、WebKit、成员和管理端覆盖。Browser plugin 不可用，本次使用仓库已有 Playwright。

无数据库/API/积分规则变更，无需 migration。应用回滚会恢复之前的字体和资源加载方式。需与发布链路的图片缓存目录权限修复一起验收；仍需维护者自审及正式发布确认。
