# 会话和首页读取优化

普通接口此前通过 `Session -> User -> PointAccount` 读取完整记录，即使只需要成员 ID 和角色，也读取了密码哈希、绑定手机号密文、头像及账户。首页还在视频状态分组之外单独统计已通过数量，增加一次查询，两个结果在并发审核时也可能来自不同时间点。

## 当前行为

- `currentUser()` 用数据库中的有效会话和启用状态过滤成员，仅选择 ID、快手 ID、昵称、角色、启用状态。`requireUser`、管理员、审核员等服务端权限检查复用这一最小身份。
- 不缓存会话、角色、启用状态或余额。退出、停用、角色变更仍在后续请求即时生效。会话到期时即无效。
- `/api/me`、`/api/member/home`、兼容 `/api/dashboard` 显式调用 `currentUser({ profile: true })`，额外选择头像、公会状态、邀请状态及账户 ID/余额。API 的成员 DTO 不变；没有积分账户时仍返回余额 0。
- 修改资料也使用相同字段选择。密码修改接口自行读取当前成员的密码哈希用于 Argon2id 校验，普通身份函数不再返回凭据。旧密码校验、改密事务、审计、旧会话删除和新 Cookie 行为保留。
- 首页 `summary.approvedVideos` 与 `videoCounts.approved` 使用同一次状态分组结果。成员资格和生日福利只读取响应需要的字段，接口结构不变。

## 测量和验证

同一合成成员、同一本地 PostgreSQL、当前 Prisma 版本，记录实际 SQL 事件：

| 身份读取方式 | SQL 数量 | 读取密码哈希 | 读取账户 |
| --- | ---: | --- | --- |
| 原有完整关联读取 | 3 | 是 | 是 |
| 普通接口最小身份 | 1 | 否 | 否 |
| 页面资料与余额 | 2 | 否 | 是，仅 ID/余额 |

此外，首页业务查询去掉 1 次独立已通过视频计数。这里统计数据库往返和字段，不将 SQL 数量降幅声称为线上响应时间降幅。线上收益仍需要整合发布后的接口延迟、数据库等待及慢查询数据验证。

`tests/session-read-path.integration.test.ts` 使用真实数据库验证查询数量与字段、余额即时读取、无 Cookie、过期/撤销/缺失会话、停用账号、角色变更、无积分账户及密码修改后旧会话失效。`tests/member-home-route.test.ts` 验证统计一致性和成员资格/生日兼容数据。先在旧实现复现了 3 项读取/统计失败，再验证修复。

本批本地通过 lint、151 项普通测试（另 71 项数据库测试跳过）、222 项全量数据库测试、生产构建及生产依赖审计（0 漏洞）。浏览器和容器最终结果记录在对应 PR；正式发布仍须通过整合后的 staging 和 [自动发版门禁](AUTOMATIC-RELEASE.md)，不要求逐次人工审查。

## 发布和回滚

无 migration、环境变量或前端合约变化；可使用配套旧应用版本回滚。角色权限、会话 Cookie 和密码安全策略保持原约束。此批不包含成就派生计算、积分事务外任务、图片资产迁移及线上延迟监控，分别在后续独立改动处理。
