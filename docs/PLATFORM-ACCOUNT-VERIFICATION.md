# 平台账号控制权与视频作者校验

关联审计工作项 #105 / B3。实现采用管理员核验挑战的方式；不要求成员提供密码、Cookie、手机号或私密对话截图。**目前真实快手页面的完整 JSON 与内部 UID 格式仍待有效公开作品样本确认，不能仅凭合成测试直接开放生产积分发放。**

## 规则

登录用的快手 ID 继续保持大小写不敏感、唯一且不可由成员修改。平台内部作者 UID 是独立字段；它不是昵称、展示用快手号或抖音 `sec_uid`，不得相互代替。

普通视频只根据同一作品的可信作者 UID 与已验证的平台绑定自动判断归属。昵称仅作为展示和诊断信息；改昵称不会解除绑定，同名也不能获得他人的视频积分。没有 UID、证据版本不支持、未绑定、绑定给别人或绑定已撤销时，自动驳回并给出验证提示。申诉通过同样检查 UID 绑定，不提供昵称兜底或管理员跳过归属校验的参数。

已有已通过视频和积分不回填、不重算。历史申诉缺少 UID 时，需要对原记录重新抓取以取得作者证据。绑定核验本身不发积分、不自动重抓全部记录；保留原视频的提交时间和既有申诉入口。

## 成员与管理员流程

1. 成员提交自己的公开视频，系统抓取作品。即使暂时不满足点赞或归属条件，只要取得可靠作者 UID，仍可作为验证参考。
2. 在“我的 → 平台账号验证”选择该作品。服务端从成员自己的抓取记录取得平台与 UID，客户端不能指定他人的 UID 或成员 ID。
3. 系统生成 144 bit 随机挑战，72 小时有效。成员使用该 UID 对应的平台账号，把完整挑战码发送给负责核验的团管理员，或临时展示在实际账号简介中。
4. 管理员进入“账号归属核验”，在真实平台确认发送者或简介所属账号的内部 UID，与申请中的 UID 相同，并确认本次挑战码。**同名主页、只有公开主页链接、他人转发消息或截图均不够。若平台界面无法可靠核对内部 UID，不能通过验证，应采用可信的平台接口或补充核验渠道。**
5. 管理员输入实际取得的挑战码、选择核验渠道、记录核对时间与方法（20—1000 字），明确确认控制权。管理列表不返回预期挑战码，避免从后台直接复制后误当成外部证据。管理员不能核验自己的账号。
6. 通过后，成员可对原驳回视频申诉，或由管理员对原记录请求重抓。普通视频依然由系统自动审核；账号核验与视频人工二次审核是不同操作。

核验记录为管理员的人工证据确认，不等同于平台 OAuth 签名证明。不要在说明中粘贴密码、手机号、地址或私密聊天原文。若需要自动验证，应另行接入获授权的平台能力，不能把公开昵称匹配重新启用为替代方案。

## 并发、撤销与追溯

- 每个成员每个平台最多一个有效绑定、一个待处理挑战；同一个平台 UID 全局唯一。绑定撤销后 UID 仍保留原归属，不释放给其他成员。
- UID 的成员与平台归属由数据库触发器保护，不能静默转移。误绑定纠正须单独核实、留存审计并走受审查的修复流程，不能通过修改昵称或自行解绑绕过。
- 核验状态、绑定与审计在同一事务更新；重复核验要求操作者和证据内容相同，改变内容的重放返回冲突。
- 积分入账与申诉通过在同一事务锁住视频、校验绑定并写入账、状态、审计。撤销绑定与入账共用作者 UID 锁；等待撤销完成的入账会重新检查绑定状态。
- 撤销只阻止后续入账，保留历史视频、积分、核验证据与审计；历史错账仍使用原有受审计的撤销、补偿流程。

## 抓取证据边界

快手解析使用有限大小的 JSON 文档与明确关联的作品/作者结构，不执行页面脚本、不拼接独立正则取得的点赞数和作者。跳转后的作品地址必须给出可识别的作品 ID；目标作品不明确、同一作品数据冲突或返回结构不支持时失败；缺少稳定 UID 不能继续入账。抖音只从目标 `aweme_id` 对应详情的 `author.uid` 取作者身份。

快手每一次跳转都在请求前校验 HTTPS 和精确平台域名，最多 5 次，整段有超时和大小限制；非完整 200 响应不作为证据。抖音主页面导航只允许平台域名，详情数据只接受官方主域下两个明确接口路径。链接查询参数中的 `userId`、昵称或第三方同路径响应不能充当作者证据。

公开页面结构可能变化。当前实现支持的结构需通过真实公开样本验收后再上线；新增结构应添加脱敏夹具和失败用例，不能因为抓取成功率降低而恢复跨对象拼接或去掉来源校验。

只读复查脚本按作品平台选择抓取器，核对已保存的作者 UID 与历史绑定 ID。缺少历史证据时标记 `legacy-author-evidence-unavailable`，不根据今天的昵称或绑定反推过去冒领；绑定今天被撤销也不使历史入账失效。抓取失败与证据缺失分别报告，不自动扣分。积分规则快照复查同时依赖 PR #119，自动审核政策依赖 PR #108，最终需合并验收。

## 迁移与发布

新增 migration：`20261003210000_platform_author_bindings`。它只新增视频证据列与绑定/挑战表、索引和约束，没有给历史成员自动绑定账号，没有改写已执行 migration。

发布前必须完成脱敏生产副本演练、真实平台样本验证和成员验证指引，确认管理员能核对实际内部 UID。切换时限制高风险写入并排空 Worker，确保 Web/Worker 同一版本。旧 Worker 和旧申诉代码不识别新的绑定限制，不能混跑；退回旧版前必须保持相关入账入口关闭，优先前向修复。数据库新增表和审计记录保留，不做直接降级删除。

本地验收使用合成账号、合成作品与模拟平台证据；它验证事务、接口和 UI 行为，不证明真实平台账号已被核验。验证范围包括昵称伪装拒绝、已绑定作者改名通过、申诉无法绕过、同 UID 并发争用、过期挑战、跨成员请求、重复处理、撤销与入账锁竞争，以及 390×844 / 1440×900 的加载、空数据、失败恢复与完整核验流程。
