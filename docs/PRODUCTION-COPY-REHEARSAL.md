# 生产副本迁移演练

`Isolated Production Copy Rehearsal` 由可信 main 工作流执行，输入必须是同仓库完整 CI 已成功的确切 commit。只传递该 commit 的 Prisma schema / migration 文件和 main 中的固定演练脚本，不启动候选应用。

持有发布锁后，使用已校验的现有备份恢复到生产主机上的临时 PostgreSQL 容器。容器没有网络、映射端口或持久卷，数据仅存于受内存限制的 tmpfs；Prisma CLI 复用已存在的 Worker 镜像，加入这个隔离网络命名空间，无法连接生产数据库或互联网。所有原始备份、恢复日志和数据库行均留在主机，结束清理仅限本次演练容器和私有临时目录。生产服务不停止，不执行生产迁移。

恢复后先删除副本 Session，再替换平台账号、链接、昵称、密码哈希、电话地址密文及自由文本，清空 JSON 和生日字段；内部关系 ID、枚举、金额、积分和状态保留。脱敏仅可在固定副本数据库名及额外 guard schema 同时存在时执行。JSON 脱敏意味着本演练验证历史结构、迁移兼容和数值保持，业务分支行为仍由完整数据库集成及 staging 测试验证。

验证旧 migration 校验和未被修改，执行新 migration、重复执行、schema 差异检查，对比脱敏前后与迁移前后的账号、视频、流水、榜单、兑换计数及余额/流水汇总。输出仅包含版本、备份文件名、汇总值、migration 校验和及检查布尔值。真实故障日志不上传，避免错误 SQL 回显生产数据。

首次升级限定备份 ≤128 MiB、可用内存 ≥2 GiB、可用磁盘 ≥3 GiB；超限停止，不自动扩大资源占用。每次结果绑定候选 SHA 和备份，不能把其他版本或纯模拟测试称为生产副本演练。

失败记录区分恢复余额、脱敏 SQL、汇总一致性、历史 migration 和校验和等阶段，仅提取固定格式的 SQLSTATE 错误码。退出时清理隔离容器，再检查其已移除、生产容器未重启及健康状态；失败证据同样留存，不上传错误 SQL、行内容或原始日志。

实际演练 `37183609516` 已确认脱敏和积分守恒通过，阻塞点是历史 migration 校验和；失败后隔离容器已移除，生产服务保持健康。演练遇到校验差异时可以继续在隔离副本中收集证据，但结果仍为不合格，不能发布，也不修改 `_prisma_migrations`。同一无网络容器内从候选 SQL 新建空参考数据库，对比迁移后的逻辑结构，覆盖列、默认值、约束、索引、枚举、函数和触发器等；不把仅 Prisma schema 相同当作数据库约束已验证。结构一致不自动批准未知的历史校验差异。
