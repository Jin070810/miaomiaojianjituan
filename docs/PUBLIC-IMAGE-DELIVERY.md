# 公开图片缓存与商品分页

关联审计 #105 / P3。商品图和头像原来作为 base64 字符串重复包含在业务 JSON 中；本变更让浏览器单独缓存图片，同时保留现有数据库存储与备份方式，不引入额外存储服务。

## 图片来源与缓存

- 成员接口将数据库中的 WebP data URI 转换为 `/api/public-images/gift/<id>/<sha256>.webp` 或 `/api/public-images/avatar/<id>/<sha256>.webp`。原文件字节留在原字段，不做历史数据回填或 migration；已有静态路径、外部图片 URL 保持兼容。
- 图片版本来自完整原值的 SHA-256。图片改变后返回新 URL；服务端只在版本完全匹配时返回原字节，旧 URL 不会静默变成新图片。匹配响应使用 `public, max-age=31536000, immutable`、ETag、`image/webp` 和 `nosniff`，支持 `If-None-Match` 的 304。错误响应不缓存。
- 首次未缓存访问仍读一次数据库中的指定图片字段；后续新鲜缓存访问由浏览器处理。本次不宣称数据库存储量、SQL 取回图片字节或首次图片传输量下降。管理员编辑接口保留原图片值，避免把生成的展示 URL 写回为图片来源。
- 此接口只允许 `gift` 与 `avatar` 两类，检查 ID、版本、WebP 文件头、长度和大小上限，不接受任意表名、字段名或远程 URL，不代服务器请求外部地址。礼品停售后的历史订单仍可显示其图片；删除礼品、停用成员或更改图片后，源站旧请求返回 404。已经缓存或保存的公开图片不能被远程收回。
- **收款码、地址、手机号和履约资料不进入这条公开缓存链路**。它们继续使用原有权限与脱敏接口；此端点不读取这些字段。头像和商品图本身被定义为公开展示素材。

覆盖成员首页、资料/头像保存响应、榜单、生日墙/祝福/奖品、兑换记录与旧 dashboard 接口的图片序列化。这里没有缓存成员身份、余额、库存或权限。

## 商品分页与兼容

新版礼物屋请求 `/api/gifts?page=1&take=24&sort=featured`，支持 `category` 和 `featured / sales / priceAsc / priceDesc`。页大小最多 50，非法页码、排序和分类参数返回 400。分类来自全部上架商品，而不是只来自当前页；排序在服务端对整个筛选范围执行，使用固定次序处理同分。销量只计算非驳回、非退款订单，按数量求和。

加载更多保留已有卡片；失败后可重试同一页；分类与排序变化取消旧请求并重置结果，晚返回的旧请求不能覆盖新选择。图片使用浏览器懒加载，控制按钮至少 44px。库存与余额以兑换事务的实时校验为准。

兼容窗口保留无参数 `/api/gifts` 的完整 `gifts` 数组，图片仍替换成可缓存 URL；新增字段为 `categories` 和 `pagination`。新客户端也能显示缺少这两个字段的旧响应。**旧无参数入口尚未强制分页**，应在确认旧客户端退出后单独移除兼容路径；不能把新版的单页性能改善说成所有旧调用都已受限。

普通排序只汇总当前页礼品的销量；销量排序使用聚合结果决定整类的分页位置，并复用该结果，不再重复聚合一次。没有凭推测添加新的数据库索引，后续依据真实查询计划和订单量决定。

## 验收与回滚

先在旧实现复现分类/分页/排序参数被忽略，再验证 3 个真实 PostgreSQL 集成用例。图片边界包含独立缓存、304、旧版本失效、非法内容/尺寸、私密类型拒绝与来源限制。浏览器验收覆盖 390×844 和 1440×900 的分页、全局排序、加载、失败重试、空数据、禁用兑换、旧响应兼容及兑换弹窗。

浏览器测试使用合成商品和随机纹理 WebP，记录转换前后原始 JSON 字节到 CI 产物；这是可重复的本地/CI 对照，不代表生产带宽或真实用户 LCP。最终发布还需与其他访问性能变更一起验收。

没有数据迁移、图片搬迁或余额修改。回滚应用后旧接口仍能读取原 data URI；已发出的版本 URL 在旧程序中可能 404，旧页面刷新后恢复原图源。切换与回滚仍通过已审查 release commit，并保持 Web / Worker 同版。
