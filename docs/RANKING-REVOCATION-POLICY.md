# 视频撤销后的历史榜单与奖励处理

本次实现采用维护者确认的口径：保留历史榜单，冻结未发奖励，已发奖励生成审计调整待办。适用对象是周更新榜、月点赞榜的 `RankingPeriod` / `RankingAward`；周挑战和限时竞赛的积分补偿仍执行其各自规则。

## 结算与历史证据

- 新结算在同一事务内保存规则、全部有效贡献视频、排名、奖励和审计。贡献集合由一条 `INSERT ... SELECT` 固定，排名只对这一集合聚合，不再二次读取可变的视频状态。
- `ruleSnapshot` 记录规则版本、上海时区、按提交时间归属、统计指标、参与角色、排序及名次上限、奖励文字。周榜按视频数，月榜按点赞数；并列依次比较视频数、点赞数和成员 ID，保持原算法。
- `RankingContribution` 保存视频 ID、成员 ID、提交时间和结算时点赞数。已结算预览和历史查询读取已保存的 `RankingEntry`，撤销不会重排、递补或修改原名次和成绩。
- 时间范围为上海周期的左闭右开区间。Prisma 时间列是 UTC `timestamp`，原始 SQL 明确把绑定时间转成 UTC，避免数据库会话时区改变边界。
- 历史周期不回填推测数据。`contributionsCapturedAt` 为空表示缺少历史明细；撤销时对该成员相应周/月周期奖励创建 `LEGACY_WINDOW` 待办，界面要求先核实相关性。新周期只有确实进入贡献快照的视频才会触发冻结，结算后才通过的视频不影响已结算奖励。

## 奖励状态与处理

| 撤销时奖励状态 | 处理 | 管理员可用操作 |
| --- | --- | --- |
| `PENDING` / `CLAIMED` | 创建 `FREEZE_UNPAID`，保留原领奖状态与库存预留，禁止领取、发放和换礼品 | 解除本项冻结；取消整个奖励 |
| `FULFILLED` | 保留已发记录，创建 `REVIEW_PAID` | 记录实际调整完成；说明无需调整 |
| `EXPIRED` | 不重复建立冻结 | 保留历史记录 |

冻结使用独立记录，不改动旧奖励枚举。一个奖励存在多条撤销视频时会有多项冻结；仅当全部解除后才可继续领取或发放。取消奖励会一次关闭全部未发冻结、将奖励标记为 `EXPIRED`、恢复预留礼品库存一次，并逐项写审计。已发奖励不自动扣积分或回收实物；管理员应完成实际核实/线下调整后填写 5–1000 字依据。

成员列表新增可选 `frozen`、`adjustmentPending`，冻结按钮禁用、待领取计数剔除冻结奖励。管理后台“榜单结算”新增分页待办、已处理记录、错误重试及操作影响确认。调整接口只允许服务端 `ADMIN`，`MEMBER` 和 `REVIEWER` 均拒绝；写入检查同源。返回数据不包括收货密文和地址，收货明文仍走原有专用查看审计接口。

## 事务与幂等

1. 撤销按周、月顺序取得周期事务锁，再撤销视频和补偿积分；结算取得同一周期锁后认领结算状态。因此先结算会产生准确快照及后续冻结，先撤销会从结算贡献中排除。
2. 领取、发放、冻结、调整都先锁定奖励记录，再检查状态。发放先完成则记录已发核实；冻结先完成则拒绝发放。
3. 奖励与视频的唯一约束防止重复待办。已关闭待办只有同一操作者、处理方式、依据的重试才返回原结果；不同处理结果拒绝覆盖。
4. 库存、状态、通知和审计在同一事务提交。数据库触发器阻止旧写入路径绕过已经存在的未发冻结，约束拒绝缺少处理人、时间或依据的已关闭记录。

审计动作：`RANKING_AWARD_FROZEN`、`RANKING_AWARD_ADJUSTMENT_OPENED`、`RANKING_AWARD_ADJUSTMENT_RESOLVED`、`RANKING_AWARD_CANCELLED`。待办保留撤销时的奖励和视频证据；历史缺失证据明确标注，不伪造历史点赞数。

## Migration 与回滚

新增两项 migration，不修改已执行历史：

- `20261003160000_ranking_revocation_evidence`：可空规则字段、贡献/待办表、索引、约束和冻结保护触发器。
- `20261003160500_ranking_adjustment_resolution_not_null`：补充明确的非空约束，避免 PostgreSQL `CHECK` 的 NULL 三值逻辑放行不完整处理记录。

先备份并在生产脱敏副本演练，再执行 migration，最后同时切换 Web/Worker。迁移不扫描回填历史榜单，也不自动处理已有奖励。本地合成数据和 CI 空库迁移不能替代生产副本演练。

保留所有新增表、触发器和审计，禁止回退/删除数据库历史。旧应用虽然会被触发器阻止领取已有冻结，但不会为新撤销生成待办，因此不能直接退回旧版本继续开放奖励与撤销操作。事故优先在网关限制视频撤销、榜单结算、领奖、发放及调整写接口，并停用可能处理普通二审撤销的旧 Worker 路径；保留读服务和证据，优先前向修复。应用回滚只有在这些写入口已隔离、Web/Worker 同版本且维护者确认后进行。

## 验证与验收

本地 PostgreSQL 集成覆盖 13 项场景：撤销前后历史不变、冻结后领取/发放拒绝、贡献与规则快照、迟到视频、旧周期缺证标记、已发记录保留、重复撤销/调整、多个冻结和一次性库存恢复、旧写入触发器保护、发放并发，以及确定性模拟结算先行/撤销先行。

`tests/e2e/ranking-adjustments.spec.ts` 在 `ranking-mobile`（390×844）和 `ranking-desktop`（1440×900）验证管理员登录、读取失败/刷新、加载禁用、保存失败/重试、处理影响确认、取消库存、已发无需调整、解除冻结、空待办、成员冻结展示和成员/审核员 RBAC。截图保存于 CI Playwright/staging 附件的 `ranking-*.png`。新操作按钮至少 44px，无页面横向溢出。
