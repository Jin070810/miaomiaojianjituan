# 对账和运维告警规则

关联 #105。data:reconcile 和 ops:daily-check 共用 lib/integrity-reconciliation.ts，并在 PostgreSQL Repeatable Read、READ ONLY 事务内读取账户、流水和订单；正常并发入账不会因两次读取跨越提交时间而被误判为错账。此模块只检查，不改余额、订单、奖品或审计历史。

普通兑换订单要求数量为正、单价至少 1、总价等于数量乘单价。生日免费商品订单必须同时满足：存在 birthdayPrizeId、奖品为已领取 GIFT、商品和所属成员一致、数量恰为 1、单价和总价均为 0。订单后续发货或退款不会使这份领取关系失效。普通零价订单、错成员/商品、未领取奖品或异常金额仍报错；乘法提升为 bigint，异常大整数不能使检查本身溢出。

负余额始终保留在 negativeBalances。只有余额与全量流水合计一致，并且造成负余额的扣减都能对应原始奖励和补偿审计，才归为 compensatingDebts（需跟进的业务欠额）。涵盖视频及生日加成撤销、带审计的视频积分纠正、周挑战和竞速奖励冲正；同一来源累计扣回不能超过原入账。竞速获奖记录可能换人，使用原 assignment、原账户流水和幂等标识核对，不能用当前获奖者误判旧冲正。

无法解释的负余额归为 unexplainedNegativeBalances，包括普通转账透支、仅伪装成 REVERSAL 类型却没有审计依据、重复过度冲正、缺失原始奖励或余额合计不符。它们继续使对账命令非零退出，并触发 critical 运维告警。合法补偿欠额仅产生 warning，data:reconcile 不因此非零退出；不会自动清零、补发、免除欠额或解除余额校验。

两项检查现在同时覆盖余额合计、未知负余额、重复有效 photoId、礼品库存/价格、订单价格和整数流水。每日巡检还保留 Redis、Worker、队列、周挑战、清退及备份检查。订单异常最多返回前 20 个样本；非空即失败，不代表全库只有这些异常。

集成测试覆盖合法生日零价订单及后续状态、普通零价/错误归属/错误金额、整数乘法溢出、已审计补偿、普通透支、无审计补偿、过度冲正、视频纠正、竞速换人以及并发事务提交期间的快照一致性。无数据库 migration，也不借对账脚本修改生产数据。
