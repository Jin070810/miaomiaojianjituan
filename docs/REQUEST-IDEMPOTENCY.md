# 写操作的请求重试约定

关联 #105。转账、兑换、视频提交、管理员单笔/批量积分调整都必须把幂等标识绑定到原操作人及原申请。同一个标识换人、换金额、换对象或更改申请资料，返回 HTTP 409，不返回旧业务记录，不执行新的扣款、入账、库存占用或视频入队。不要在收到 409 后自动生成新标识重试；应先查看历史记录确认结果。

- 转账核对转出人、转入人、金额和备注；正常返回与数据库唯一键竞争后的回退执行相同核对。
- 视频核对成员及原始链接归一化结果。Worker 把短链接解析成长链接后，仍以保留的 sourceUrl 为准；分享文案的无关变化不产生新申请。通过核对的 PROCESSING 重试可以补充入队。
- 兑换在同一事务的 REDEMPTION_CREATED 审计中记录版本化 HMAC 摘要，包含成员、礼品、数量、备注、原始收货/收款/权益资料及请求标识。审计不记录这些资料明文。对象键的顺序、首尾空白不影响摘要；资料的省略与显式提供是不同的申请。重试不重新读取成员当前收货档案，也不重新使用当前礼品价格。
- 管理员单笔调整核对目标、金额、原因及原审计操作人；批量调整核对操作人、选人模式、去重排序后的显式成员集合、金额及原因。对 ALL_ACTIVE_MEMBERS 的合法重试返回当时批次，不把后来加入的成员补入原批次。
- 管理员调整先按请求标识取得数据库事务锁，避免同一个标识同时用于两个互不相交的成员集合。批次按精确 referenceId 和业务类型读取，不能用字符串前缀代替批次归属。

新摘要使用现有 PHONE_ENCRYPTION_KEY 做 HMAC，并加作用域和版本前缀。与现有加密数据一样，轮换密钥时需要配套迁移/密钥读取兼容，不可只替换环境变量。新规则无数据库结构 migration，摘要随原业务审计原子保存。

旧版兑换和批量调整没有原申请摘要，无法证明资料或选人模式是否一致，重试返回上述通用 409；历史记录和原订单保持可查看，不自动重建或再次扣款。旧版转账、视频和单笔调整在已有字段足以证明归属和内容时继续支持重试。回退旧应用版本会重新引入越权重放风险，应优先前向修复。

兑换 POST、合法重试和 GET 共用成员订单 DTO，省略手机号/地址密文、收款码和权益资料密文，仅返回是否已提供这些资料的布尔标识，保留既有状态、履约时间等字段。管理员经权限校验后的履约资料查看接口不在本次响应变更范围。

验证包括真实 PostgreSQL 并发、唯一键竞争后的回退、不同成员/参数重放、收货档案变更、权益资料变化、旧版记录、单笔与批量标识碰撞，以及 API 敏感字段断言。发布前仍需 CI、staging 验收与维护者审查；本文不表示已上线。
