## 组合时修正的交互

- Worker 原先先锁视频行，再等待 photoId；申诉按相反顺序获取锁。整合后统一为 photoId → 视频行，并用真实锁等待测试证明等待 photoId 时不会占住视频行。
- 规则快照计算、作者昵称校验和数据库处理租约共同保护同一次入账。队列重试次数与请求 trace 同时保留，不恢复旧的无限重建队列行为。
- 拆出的首页成长卡保留后台读模型的 pending/stale 状态和有限退避刷新；测试通过显式后台重建准备数据，不把计算搬回 GET。
- 轻量 Worker 保留 supervisor、成长重建 CLI、Prisma migration 和运维脚本；元数据仍放在 Dockerfile 后层，Web 图片缓存目录保持非 root 可写。
- CI 保留完整浏览器项目矩阵、依赖故障演练、Worker 运行时检查及发布控制器演练。删除旧的重复构建路径，不以缩减验收来换取提速。
- 按所有者确认，保留现有爬取方案，不引入 UID 绑定。正常抓取和昵称匹配的成员可继续自动入账，无需新增绑定数据。
